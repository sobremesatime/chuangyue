# migrations · 数据库迁移

数据库结构变更的 SQL 脚本，命名规则：

```
<序号>_<动作>.sql
```

例如：

```
0001_init.sql              初始化 user / video 表
0002_video_add_index.sql   给 video 增加索引
```

## 约定

- **只增不改**：已执行的迁移文件不再修改，修正用新文件。
- 每个脚本包含升级与回滚两部分（用注释分隔）。
- 各服务只迁移自己的库，不跨库操作。
  - 例外：`0015_split_interaction_db.sql` 是「物理拆库」的引导脚本，需要一次性建互动库、搬运表结构 / 数据、建独立账号，故会跨库操作；拆分完成后各服务恢复「只动自己库」。

## 自动执行

`deploy/compose/docker-compose.yml` 把本目录挂载到 MySQL 容器的
`/docker-entrypoint-initdb.d`，因此 **MySQL 首次启动时** 会按文件名顺序自动执行全部脚本。
数据卷已存在时不会重复执行；需要重跑请先 `docker compose down -v` 清空数据卷。

## 初始化管理员账号

系统只有「管理员 / 普通用户」两级角色，而注册接口创建的账号固定是普通用户。
上传视频需要管理员权限，按以下两步初始化：

1. 在前端注册页（或调用 `POST /api/v1/auth/register`）创建一个账号，例如 `admin`；
2. 在数据库里把它提升为管理员：

```sql
UPDATE `user` SET `role` = 1 WHERE `username` = 'admin';
```

`role` 取值：`0` 普通用户，`1` 管理员。改完后**重新登录**，访问令牌里的角色才会更新。

> 为什么不直接写一个 seed 脚本？因为脚本无法预知密码，而明文密码落库不安全。
> 走「注册（密码经 bcrypt 哈希）+ 提权」这条路，既安全又不需要额外的工具。
